D1
›
Knowledge

TS 4.1 + 4.2 — Explicit criteria & few-shot prompting
D4
›
Knowledge
  • Explicit criteria over vague: "flag only when commented behaviour contradicts actual code"
  • "Be conservative" and "only report high-confidence findings" don't improve precision
  • High false-positive rate in one category undermines trust in accurate categories
  • Few-shot: 2–4 targeted examples showing reasoning for correct choice vs plausible alternatives
  • Few-shot enables generalisation to novel patterns — not just matching pre-specified cases
Skills ★
  • Write review criteria defining exactly which issues to report vs skip — no vague confidence filtering
  • Identify a high-FP category — disable it, document the strategy for fixing it separately
  • Write 3 few-shot examples: each shows correct answer AND why the plausible alternative is wrong

TS 4.3 — Structured output via tool_use and JSON schemas
D4
›
Knowledge
  • tool_use with JSON schema = most reliable structured output — eliminates JSON syntax errors
  • tool_choice "auto": model may return text. "any": must call a tool. Forced: must call specific named tool.
  • Strict JSON schemas eliminate syntax errors but NOT semantic errors
  • Nullable fields prevent model fabricating values — critical for extraction accuracy
  • Enum + "other" + detail string: extensible categories without hallucinating new enum values
Skills ★

  • Add format normalisation rule for dates — verify both "Jan 1, 2024" and "2024-01-01" normalise correctly
